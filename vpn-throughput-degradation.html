Why VPN Throughput Never Matches Link Speed

Every VPN tunnel wraps your original packet inside a new one — adding outer IP headers (20 bytes), UDP/TCP headers (8–20 bytes), protocol-specific framing, initialization vectors (IV), and authentication tags. For a 1420-byte MTU payload, WireGuard adds 60 bytes of overhead (4.2% loss), while IPsec ESP in tunnel mode adds up to 73 bytes (5.1%). These numbers compound with TCP MSS clamping — if the inner TCP stack doesn't know about the reduced MTU, packets fragment and throughput collapses.

The TCP-over-TCP Meltdown

OpenVPN in TCP mode suffers from a fundamental protocol flaw: two TCP layers compete for retransmission control. When the outer tunnel TCP retransmits, the inner TCP also retransmits — creating a multiplicative backlog that can consume 20–30% of link capacity. Always prefer UDP-based VPN transports (WireGuard, IPsec, OpenVPN UDP) for anything carrying TCP traffic.
